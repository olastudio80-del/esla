# esla — передача проекта

Документ для того, кто продолжит работу. Состояние на 2026-11-23.

Всё, что здесь написано, проверено командами и запросами, а не взято из
памяти. Где что-то не проверено — так и сказано.

---

## 1. Что это

Мобильное приложение для Узбекистана: напоминает пожилым и хронически
больным людям принимать лекарства, а их детям показывает, как у родителей
дела. Интерфейс на узбекском и русском.

Главная мысль, из которой выросли все решения: человек, который перестал
принимать лекарства, обычно перестаёт и открывать приложение. Поэтому
важное замечает сервер, а не телефон.

## 3. Что работает и чем это доказано

**Работает и проверено:**

- **Сборка.** Android и iOS собираются в CI. Последние прогоны зелёные.
- **Телеграм-бот.** Отвечает: запрос `getMe` вернул `esla_eslatma_bot`.
- **Серверные функции.** Обход расписания отвечает 200 и оставляет запись
  в журнале отправок — то есть действительно находит человека и доходит
  до отправки.
- **Firebase.** На отправку с заведомо неверным токеном Google ответил
  «The registration token is not a valid FCM registration token». Это
  ответ про токен, а не про то, кто мы: ключ принят, подпись верна.
- **Регистрация push на живом устройстве.** В базе лежит настоящий
  FCM-токен Android длиной 142 символа. Кто-то поставил приложение, выбрал
  роль родственника и телефон зарегистрировался.
- **Разграничение доступа.** 17+ проверок: посторонний не видит чужих
  подписчиков и устройств, не удаляет их, не может записать чужой токен на
  себя (отклоняется политикой), серверные функции недоступны приложению.
- **Чистые функции.** 38 тестов: поиск по справочнику, работа с датами,
  проверка сочетаний лекарств.

**Не проверено никем и никогда:**

- **Приложение ни разу не видел ассистент.** Ни одного экрана. Всё, что
  утверждается про интерфейс, — это типы, линтер и тесты, но не живой
  экран. Баги вроде панели вкладок под системной навигацией и сломанного
  поля года рождения нашёл человек глазами.
- **Узбекское офлайн-распознавание речи.** Нужен живой телефон. В
  приложении есть экран «Проверка голоса» (Настройки → Проверка голоса),
  он сам покажет, что телефон умеет и чего не хватает.

**Что сейчас мешает увидеть тревогу вживую:**

В базе **ноль связей** «родитель ↔ ребёнок» (`esla.links` пуст), и ни один
телефон пациента ни разу не отправлял состояние (`last_seen_at` везде
пуст). Пока нет связи, тревоге некуда идти — ни push, ни телеграм. Чтобы
проверить насквозь, нужно: на телефоне пациента взять код приглашения
(Настройки), на телефоне родственника ввести его, открыть «Holat».

## 4. Архитектура

### Приложение

Expo SDK 58, React Native 0.88, React 19.3, expo-router, Hermes,
React Compiler включён. ~10 900 строк в `src/`.

- `src/app/` — экраны (каждый файл = экран, `_layout.tsx` = навигатор).
  Ничего, кроме экранов, туда класть нельзя.
- `src/db/` — локальная SQLite: лекарства, дозы, записи самочувствия,
  документы. Приложение работает **полностью без интернета**; облако —
  только для связи с родственником.
- `src/features/` — напоминания, голос, здоровье (браслет), облако, push.
- `src/data/` — справочник лекарств (8904 записи, 1807 действующих
  веществ, из госреестра) и правила сочетаний.
- `src/i18n/` — узбекский задаёт набор ключей, русский обязан его
  повторить (проверяется типами).
- `src/theme/tokens.ts` — **единственный источник правды по цвету и
  размерам**. Менять только там.

Роли: `patient` (принимает лекарства) и `relative` (следит). У них разные
вкладки и разные главные экраны.

### База

Таблицы лежат в схеме `esla`, наружу смотрят представления `public.esla_*`
с `security_invoker = true`. Так сделано потому, что схема `public` открыта
для API всегда, а открытие своей схемы требует настройки в панели.

**`security_invoker` здесь обязателен.** Без него представление читало бы
данные правами владельца и обошло бы разграничение доступа целиком.

Таблицы: `profiles`, `links`, `shared_doses`, `shared_vitals`,
`shared_alarms`, `telegram_subscribers`, `push_devices`, `notify_sends`.
На всех включён построчный доступ.

Вход анонимный (`signInAnonymously`) — пожилой человек не должен
регистрироваться. Поэтому линтер Supabase ругается на «анонимный доступ» ко
всем таблицам: **это ожидаемо**, каждая политика сверяется с `auth.uid()`.

Миграции в `supabase/migrations/`, 13 штук, применены по порядку.

### Серверные функции (Supabase Edge Functions)

- **`telegram-bot`** — вебхук бота. Подписывает близких по коду
  (`/start КОД` или просто код сообщением), отписывает (`/stop`), отдаёт
  приложению своё имя (`/info`), регистрирует вебхук (`/setup`).
- **`notify-relatives`** — отправка тревог. Три повода: тревожный симптом
  (зовёт приложение), неотмеченный приём и долгое молчание телефона (их
  находит расписание в базе, раз в час, `cron.job` `esla-silence-sweep`).

Оба канала — телеграм и push — отправляются **из одного места**, и решение
«отправлять или нет» принимается **один раз** в базе (`esla.notify_claim`).
Иначе второй канал получал бы отказ по задержке, которую поставил первый.

Push идёт **прямо в FCM**, без службы push-уведомлений Expo: та
потребовала бы учётной записи Expo и загрузки туда ключей Firebase.

## 5. Секреты

**Правило: настоящие ключи никогда не проходят через чат.** Их вводит
человек сам, в панели.

| Имя | Где лежит | Состояние |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Supabase → Edge Functions → Secrets | задан |
| `FCM_SERVICE_ACCOUNT` | Supabase → Edge Functions → Secrets | задан |
| `ANTHROPIC_API_KEY` | Supabase → Edge Functions → Secrets | **не задан**, нужен для невыполненного анализа |
| `SUPABASE_ACCESS_TOKEN` | GitHub → Secrets → Actions | **не задан**, поэтому функции не разворачиваются из CI |

Не секреты, лежат открыто и так и должно быть:

- **Публикуемый ключ Supabase** в `app.json` — он попадает в APK, и любой
  его оттуда достанет. Безопасность держится на построчном доступе, а не
  на тайне ключа.
- **`google-services.json`** в корне репозитория — он тоже внутри каждого
  APK.

**`service_role` в приложение не попадает никогда** — он обходит все
ограничения доступа.

## 6. Решения, которые не надо переделывать не разобравшись

- **Голосовой помощник без языковой модели.** Распознавание на самом
  телефоне, офлайн. Помощнику надо задать вопрос, выслушать и записать —
  для закрытого вопроса достаточно узнать знакомое слово. Это бесплатно,
  работает без интернета и не отправляет голос пожилого человека наружу.
- **Проверка сочетаний лекарств никогда не говорит «нельзя»** и никогда
  не мешает сохранить лекарство. Приложение не врач. Это закреплено
  тестом.
- **Сообщение о пропуске говорит «не отметил приём», а не «не принял».**
  Мы знаем только то, что кнопку не нажали; пожилой человек часто
  выпивает таблетку и забывает отметить. Обвинение, которое мы не можем
  проверить, било бы по отношениям в семье, ради которых всё и делается.
- **Телеграм — основной канал, push — дополнение.** Push живёт только
  пока приложение установлено, а прошивки Xiaomi, Samsung и Huawei душат
  фоновую доставку ради батареи — именно те телефоны, что стоят у
  половины Узбекистана.
- **Движение интерфейса не задерживает нажатие и не двигает то, во что
  человек целится.** Подъём при появлении 14 точек, просадка кнопки 3%.
  Промах по кнопке «Ichdim» — это незафиксированный приём лекарства.
- **Контраст считается, а не прикидывается.** Все цвета проверены
  численно. Рамка полей ввода имела контраст 1.4 (для слабовидящего её
  просто не было) — исправлено до 3.15.
- **Вызов скорой автоматом не сделан намеренно.** «Телефон не двигался
  48 часов» — слабый признак с кучей ложных срабатываний, каждое из
  которых это зря выехавшая скорая. Лестница такая: телефон спрашивает →
  близких предупреждают → **решение принимает человек**. Сделаны первые
  два шага.
- **Минимум Android 8** (`minSdkVersion 26`) — требование Health Connect.
  Ценой стала поддержка Android 7.

## 7. Ошибки, которые уже находили (и чем)

Все до одной нашлись проверками, а не чтением кода. Это и есть рабочий
метод на этом проекте.

1. **`permission denied for schema esla`** — служебной роли выдали права
   на функции, но не на вход в схему. Молча не работал **весь** серверный
   путь: подписка через бота, обход молчащих, обход пропусков. Снаружи
   выглядело исправным: функция ловит ошибку, пишет в лог и возвращает
   ноль, а HTTP-ответ остаётся `200`.
   **Урок: ответ 200 с нулями ничего не доказывает.**
2. **`link_telegram` падала у каждого близкого** — имена выходных
   столбцов перекрывали столбцы таблицы в `on conflict`.
3. **Серверные функции были вызываемы из приложения** — `revoke execute
   from public` не снимает явные права, которые Supabase выдаёт `anon` и
   `authenticated` по умолчанию. Отзывать надо именно у них.
4. **Обход расписания искал получателей только в телеграме** — семья с
   приложением, но без телеграма, не получила бы ничего.
5. **Панель вкладок уходила под системную навигацию Android** — нашла
   пользователь по скриншоту.
6. **Поле года рождения не заполнялось** — значение бралось из настроек,
   где год появляется только после четырёх цифр.
7. **План приёма уходил на сервер только при нажатии «Ichdim»** — то есть
   ровно в том случае, который нас интересует, сервер ничего не знал.

## 8. Что не сделано

- **Анализ данных и рекомендации через Haiku 5.5** (`claude-haiku-5-5`,
  $0.10/$0.50 за миллион токенов). Просили давно, не начато. Нужен
  секрет `ANTHROPIC_API_KEY` в Supabase. Телефон для этого не нужен.
  Осторожно с рамками: не ставить диагнозов, не советовать менять или
  отменять лекарства — только показывать закономерности и предлагать
  обратиться к врачу.
- **Третий шаг экстренной лестницы** — звонок в службу спасения.
- **Push на iPhone** — нужен Apple Developer Program ($99/год) ради
  ключа APNs для Firebase.
- **Мелкая отделка** по макетам: отступы местами не один в один.
- **Проверка узбекского офлайн-пакета речи** на живом телефоне.

## 9. Ограничения окружения (почему часть работы делает человек)

Проверено командами:

- **Нет аппаратной виртуализации**: `/dev/kvm` отсутствует, флагов в
  процессоре ноль. Эмулятор Android в контейнере ассистента запустить
  нельзя.
- **`dl.google.com` закрыт** (403) — Android SDK не скачать.
  **`console.firebase.google.com` закрыт** — консоль Firebase недоступна.
  **`supabase.co` и `api.telegram.org` закрыты** — поэтому функции
  проверяются вызовом из самой базы (рецепт ниже).
- **Компьютер пользователя подключить нельзя**: механизм Remote Control
  работает с Mac и Linux, а у пользователя Windows.
- **Запись секретов из сессии заблокирована** автоматикой — секреты
  вводит человек в панели.

Отсюда разделение: код, база, серверные функции, сборки, проверки — на
ассистенте; всё, что требует браузера под личным аккаунтом, живого
телефона или эмулятора — на человеке.

## 10. Как проверять (рецепты)

**Вызвать серверную функцию, когда сеть закрыта** — из самой базы:

```sql
select net.http_post(
  url := 'https://rjakxtcpumdqjqzufskh.supabase.co/functions/v1/notify-relatives/sweep',
  headers := '{"Content-Type": "application/json"}'::jsonb,
  body := '{}'::jsonb
) as request_id;

-- затем, через секунду:
select status_code, left(content, 400), error_msg
  from net._http_response where id = <request_id>;
```

**Прочитать логи функции** (здесь видна настоящая причина, а не 200):

```sql
select timestamp, event_message
  from logs
 where source = 'function_logs'
 order by timestamp desc limit 20
```

**Проверить, что отправка действительно состоялась** — по следу в базе,
а не по коду ответа:

```sql
select kind, recipients, created_at from esla.notify_sends
 order by created_at desc limit 5;
```

**Тестовые данные всегда в транзакции с `rollback`**, и после — проверка,
что не осталось следов. Один раз написали `commit` вместо `rollback` и
оставили тестовых пользователей в базе.

**Перед «готово»**: `npx tsc --noEmit`, `npx eslint .`, `npm test`.

## 11. Особенности работы с этим проектом

Они же записаны в `AGENTS.md`, здесь — главное:

- **EAS и документация Expo закрыты сетью.** Зависимости ставятся через
  `npm install <пакет>@<мажорная версия>`, конфиг ESLint заведён вручную,
  APK собирается в GitHub Actions. Сверяться с API надо по типам в
  `node_modules/<пакет>/build/*.d.ts` — они точнее документации и
  совпадают с установленной версией.
- **Комментарии и строки интерфейса на русском и узбекском**,
  идентификаторы английские.
- **Комментарий объясняет «почему», а не «что».** В этом проекте почти
  каждое решение имеет цену, и она записана рядом с кодом.
- `ios/` и `android/` в репозитории нет — их создаёт `expo prebuild`.
  Руками не трогать, нативное поведение настраивается в `app.json` и
  `app.config.js`.
